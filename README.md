# Pavilion WebAR — iPhone Safari 시험 버전

HTML, JavaScript, WASM, 모델 파일로 구성된 정적 사이트입니다. 압축 안의 파일과 vendor 폴더를 GitHub 저장소 루트에 그대로 올리고 Settings → Pages → Deploy from a branch → main → /(root)를 선택하세요. HTTPS Pages 주소를 iPhone Safari에서 엽니다. 서버 코드나 로컬 빌드 설치는 필요 없습니다.

## 실행
카메라 AR 시작을 누르고 카메라 및 움직임 센서 권한을 허용합니다. 주변 바닥을 천천히 비춘 다음 2~4m 앞 평평한 바닥을 터치해 현관을 배치합니다. 다시 배치 버튼으로 위치를 바꿀 수 있습니다. 사람 합성 체크박스로 합성 유무를 비교할 수 있습니다.

## 구현 범위와 한계
8th Wall Distributed Engine의 SLAM으로 카메라 위치를 추적하고 Three.js로 건물을 렌더링합니다. 모델은 미터 단위로 제공하고 엔진은 absolute scale로 설정했습니다. 실제 크기 정확도는 추적 초기화와 현장 상태에 영향을 받습니다.

MediaPipe Selfie Segmenter로 카메라 영상에서 사람 영역을 분리합니다. 현실 가구의 깊이를 가림에 사용하지 않습니다. 사람의 화면상 발 위치와 배치한 바닥면의 교점으로 거리를 추정하고, 그 거리에 사람 영상을 평면으로 배치하여 가상 벽 및 가구와 깊이 비교합니다. 실제 사람의 픽셀별 깊이를 측정하는 방식이 아닙니다.

한 명의 전신이 보이는 평평한 바닥에서 시험하세요. 발이 화면 밖으로 나가면 사람 합성을 숨깁니다. 여러 사람, 앉은 사람, 계단, 가구 뒤에 가려진 다리, 잘못된 마스크에서는 깊이 추정이 틀릴 수 있습니다. 사람 분리는 약 7회/초로 수행하므로 움직일 때 합성 지연이 있을 수 있습니다. 카메라에 보이지 않는 신체 부분은 복원할 수 없습니다.

## 검증 상태
JavaScript 문법, 정적 파일 연결, 모델 파싱, 바닥 교점 및 투영 계산을 확인했습니다. 이 환경에서 iPhone Safari, 카메라, 자이로 센서, 실제 SLAM 및 사람 합성 화면을 실행 검증하지 못했습니다. 이 파일은 실기기 확인이 필요한 시험 구현입니다.

## 라이선스
- 8th Wall Engine Binary는 Niantic Spatial의 바이너리 라이선스를 따릅니다. 원본 패키지를 vendor/xr에 포함했습니다. vendor/xr/LICENSE를 확인하세요.
- Three.js 라이선스는 vendor/three/LICENSE에 있습니다.
- MediaPipe Tasks 및 Selfie Segmenter는 Google의 배포물입니다. https://ai.google.dev/edge/mediapipe/solutions/vision/image_segmenter 를 참고하세요. 배포물과 모델은 원본을 사용합니다.

## 화면 크기 수정
카메라 캔버스의 실제 픽셀 크기를 Safari의 visualViewport 크기로 초기화하고 주소창 높이 변경 및 회전 시 갱신합니다. AR 시작 후 안내 패널을 축소합니다. 위치 추적 상태는 매 프레임 확인하며 정상 복구 시 배치 안내를 다시 표시합니다. 기본 300×150 캔버스에서 세로·가로 화면으로 변경하는 로직을 검사했습니다. 실제 iPhone 화면에서의 결과는 추가 확인이 필요합니다.

## 배치 방식 수정
바닥 hitTest 결과가 비어 있을 때 배치가 계속 차단되던 조건을 제거했습니다. 위치 추적이 정상화되면 바닥에서 휴대폰까지의 실제 높이를 입력하고 “3m 앞에 배치”를 누르세요. 기본 높이 1.4m는 예시값입니다. 입력한 높이로 수평 바닥면을 정하고 현관을 앞에 배치합니다. 화면의 바닥을 터치하면 같은 수평면과의 교점에 배치합니다. 높이가 맞지 않으면 바닥이 뜨거나 가라앉으므로 다시 배치하여 조정하세요. 이 버전은 사용자가 높이를 맞추는 방식이며 위치 추적 자체가 정상이어야 배치됩니다.
